# IQ Card Phase 2: Profiles Design

## Purpose

Build the reusable profile product: each client manages one private profile, optionally imports basic LinkedIn details, previews the result, and publishes a public IQ Card URL.

## Decisions

- One account owns one profile.
- Profiles begin as private drafts and become public only after the client clicks Publish.
- The public profile visual language is based on Nikhil Rakesh’s existing dark premium card.
- The system suggests a URL from the client’s name and allows editing before publishing.
- Every profile has automatic Save Contact, Call, Email, and WhatsApp actions when the corresponding details exist.
- Clients can add ordered custom links such as LinkedIn, website, portfolio, Instagram, and payment links.
- LinkedIn import uses the official basic OAuth/OIDC flow only. Imported data is reviewed in the editor and never publishes automatically.

## Scope

### Included

- A one-to-one `profiles` database table.
- Client profile editor, draft saving, preview, publishing, and unpublishing.
- Public profile page at `/{slug}` for published profiles only.
- Slug suggestion, validation, availability check, and protected uniqueness.
- Profile photo upload to a private Supabase Storage bucket with a safely served public profile image.
- Contact-card (VCF) generation from profile details.
- Ordered custom links.
- Basic LinkedIn import entry point and OAuth callback scaffolding, guarded behind environment configuration.

### Excluded

- Admin onboarding and client-management workflows (Phase 3).
- Migration of every legacy profile (Phase 4).
- Central analytics, payments, multiple profiles, and full LinkedIn experience/education import.
- Public landing-page redesign.

## Data model

`profiles` has `id`, `owner_id` (unique reference to `user_accounts.id`), `slug` (unique), `status` (`draft` or `published`), `full_name`, `headline`, `tagline`, `bio`, `phone`, `email`, `photo_path`, timestamps, and `published_at`.

`profile_links` has `id`, `profile_id`, `label`, `url`, `sort_order`, and timestamps. Links are ordered by `sort_order` and limited in the application to 12.

RLS allows a client to manage only their own profile and its links. Public reads return published profiles only. Storage paths are namespaced by profile ID so one client cannot overwrite another client’s image.

## User flow

1. A signed-in client opens `/dashboard`.
2. If no profile exists, the app creates a private draft with a suggested slug.
3. The client completes the form, optionally imports basic LinkedIn data, uploads a photo, and saves the draft.
4. The client previews the public-card layout using the current draft content.
5. The client clicks Publish. The profile is validated and becomes visible at `/{slug}`.
6. The client can unpublish or make further draft changes, then publish them again.

## LinkedIn import

The app will offer an optional “Import from LinkedIn” action only after LinkedIn OAuth credentials are configured. It requests LinkedIn’s official `openid`, `profile`, and `email` scopes. The import maps available data to name, email, and profile photo; it does not scrape LinkedIn or automatically publish any profile information.

Required later environment variables:

```text
LINKEDIN_CLIENT_ID=
LINKEDIN_CLIENT_SECRET=
```

If these are absent, the editor hides the import action and still supports normal manual onboarding.

## Routes

| Route | Access | Behaviour |
|---|---|---|
| `/dashboard` | signed-in client/admin | Profile editor and draft/publish controls |
| `/dashboard/preview` | profile owner | Private preview of current profile content |
| `/api/contact/[slug]` | public | Generates a VCF only for a published profile |
| `/auth/linkedin` | signed-in profile owner | Starts official LinkedIn OAuth when configured |
| `/auth/linkedin/callback` | signed-in profile owner | Imports approved basic details into draft |
| `/{slug}` | public | Renders a published profile or 404 |

## Public profile design

The reusable card takes inspiration from the existing Nikhil profile: dark background, centered photo, name/headline/tagline, strong Save Contact button, optional primary custom links, contact action row, and IQ Card footer. Content is data-driven; no person-specific HTML is copied.

## Validation and safety

- Required to publish: full name and a valid unused slug.
- Slugs use lowercase letters, digits, and hyphens; reserved paths such as `admin`, `dashboard`, `login`, `api`, and `auth` are rejected.
- URLs must use `https:` except `mailto:`, `tel:`, and valid WhatsApp links generated by the app.
- Photo uploads accept JPEG, PNG, and WebP up to 5 MB.
- HTML is never accepted in profile text.
- A profile cannot be publicly retrieved until its status is `published`.

## Acceptance criteria

- A newly signed-in client can create one private draft profile.
- The client can save/edit text, contact details, photo, slug, and custom links.
- The profile only appears publicly after Publish.
- A published card generates a valid downloadable VCF.
- A client cannot access another client’s draft, image, or editor.
- A public visitor cannot access draft content.
- LinkedIn basic import is unavailable until credentials are configured and does not block manual profile creation.
